# U1 设计：日历/对话可用性修补

日期：2026-11-18
状态：已实施
范围：用户反馈的六处体验问题——聊天不跟底、约束不可见、日历不是经典周视图、没有节假日、备注不进上下文、草稿没有保存入口。

## 1. 聊天跟随底部

对话容器加 `stickToBottom` 判定：距底部 < 48px 视为跟随。用户主动上翻后停止自动滚动，回到附近自动恢复。触发源包括消息、流式增量、卡片、错误与确认态。

## 2. 方案卡可呼出

输入框上方新增 `PlanCardPanel`：一行「方案卡 · 约束 3/3 · 任务 2（未保存）」，点开就是**制定计划时那张「核对约束方案」卡片的主体**——`ConstraintSetBody` 现在由 AI 确认卡和这里共用，不再有两套任务/约束列表。

- 两处都能**直接就地编辑**：开始日、任务标题与时长、约束时间窗、互斥软硬、增删约束——与制定计划时的确认卡完全一致。
- 草稿（`plan.id === null`）：底部「保存计划」走 `POST /plans/save` 整份落库；`planFromArtifact` 保留未改动约束的 id/source/enabled。
- 已保存计划：底部「保存修改」，`diffPlanCard` 把改动转成 ops（任务按 key、约束按 payload 精确配对后按顺序配对为就地编辑），走同一个 patch 通道，可撤销。
- 卡片**向上浮出**（绝对定位锚定在入口栏上方），不挤压或遮住输入框；内容区最高 50vh 内滚动。
- 计数保留在标题行，便于一眼看出 AI 这轮有没有增删约束或任务。

## 3. 经典周视图

- 周视图只显示**锚点日期所在周的周一到周日**；日视图显示锚点当天。
- 顶栏改为「上一段 / 日期选择器 / 今天 / 下一段」，周视图步长 7 天、日视图 1 天；日期选择器可直接选年月日。
- 删除原先「相对计划首周的偏移（weekOffset）」和 `sharedHorizonStart`：锚点由用户掌握，不再随切换计划跳动。

## 4. 节假日

`shared/holidays.ts` 收录中国大陆 2026–2027 年的全国性放假日与调休上班日，数据取自 timeanddate.com 的中国节假日页（2026、2027 两份）。日历日头显示节假日名（红）或「调休」（黄）；`buildUserMessage` 把当前计划期内的节假日与调休写入上下文。

边界：只覆盖 2026–2027；2028 起需要补数据；行业性半天假（妇女节、青年节等）未收录。

## 5. 备注进入上下文

当前计划与其他计划的块行追加「备注：…」（当前计划截断 60 字，其他计划 40 字），并在 system prompt 说明备注是用户补充信息，排程时要参考。

## 6. 草稿保存

之前只有 AI `commit` 会把计划落库，手工草稿没有保存入口。新增：

- `POST /api/plans/save`：整份快照落库（标题、horizon、时区、任务、约束、块），**不跑求解**，保留手放块、钉住状态与备注；`plan_id` 为空表示新建，非空表示覆盖（version+1）；本地非 UUID 的 id 交给数据库重发；顺带把未绑定对话绑到新计划。
- 草稿改为**后台自动保存**：停止操作约 1 秒后整份落库（`useAutoSaveDraft`，只对「有内容且无云端 id」的草稿触发），不再有「保存计划」按钮；方案卡入口显示「自动保存 / 保存中… / 自动保存失败」。已保存计划本来就是服务端优先，无需保存动作。
- 新建对话时，若当前仍是未保存草稿（自动保存尚未完成），会弹确认，文案为「当前计划还没有保存到云端，新建对话会丢掉它」。

## 7. 测试

- `shared/__tests__/holidays.test.ts`：2026 春节/调休、跨年取到 2027 元旦、普通工作日为空。
- `functions/__tests__/prompt.test.ts`：节假日段、备注段。
- `functions/__tests__/plans.test.ts`：保存草稿创建/覆盖、备注与钉住保留、非 UUID id 重发、对话绑定、权限 403、时间非法 422、删除一个计划不影响其他计划。
- 既有 382 用例保持全绿（现 389）。

## 8. 未做

- 移动端回归（用户明确先不做）。
- 2028+ 节假日数据。
- 备注的按需裁剪策略：目前是「有就带上」，尚未按语义挑选。

## 9. 追问卡片（question_card）

信息不足时的追问从纯文本改成结构化卡片：

- 新 artifact：`{type:"question_card", title?≤40, questions:[{text≤140, options?[2–4 个，每个≤40]}]}`，1–3 个问题；本轮只问最关键的 ≤2 个。
- 服务端 `parseModelText` 识别并作为独立消息类型落库；历史回放同样走 artifact 事件，刷新后仍在。
- 客户端 `QuestionCard` 用站内卡片外壳：标题 + 每条问题 + 选项按钮；点选项直接作为用户消息发出，也可以忽略卡片自己在输入框回答。
- prompt 改为：信息不足优先输出 question_card，能给具体选项就给；同一轮不再输出 constraint_set / patch。闲聊才用自然语言。

这样「每周练几天」「训练时段」这类选择是点一下的事，而不是让用户对着一段列表打字。
