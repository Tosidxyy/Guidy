# 搜索与方案生成策略

确认日期：2026-10-11（Asia/Shanghai）。用户已确认组合方案方法；本文件的供应商比较与完整编排是实施建议。首批豆包Custom服务端Adapter/搜索尝试接口已实现，实际边界见[接入说明](SEARCH_SETUP.md)。首批PlanDraft后端见[草稿说明](PLAN_DRAFT.md)，手机草稿审阅已接入，自动查询/搜索Workflow及完整计划闭环尚未实现，也没有真实性价比/召回质量测试。

## 1. 已确认的主流程

确认条件 → 从验收结果倒推阶段与任务 → 判断知识缺口 → 按需检索 → 筛选/保存证据 → 生成结构化PlanDraft → 校验并修订 → 用户选择确认 → 确定性排程 → 执行反馈与局部重规划。

- 已确认的时间、预算、水平、资源、限制决定方案取舍。缺项允许带明确假设的初稿，不能擅自补为用户事实；安全/执行门槛仍按PRD。
- 非时效性且已有足够可信依据的目标可跳过搜索；外部事实、价格、专业依据或存在知识缺口时检索。搜索到不等于核验过，供应商答案不替代证据。
- 可给最多两种有明确取舍的草稿，解释投入、依赖、风险和未知项；不强制每次两份。
- 生成与审阅可用同一个DeepSeek Provider分步骤完成，输出结构化缺陷/修订点；代码校验硬约束，模型只辅助内容审阅。
- 手动来源页作为补充/测试工具，用户私人模板在V0.2，公开模板在V0.3；本轮不提前开放模板或更改导航/品牌。

## 3. 其他方法及成本控制

- 少量维护者审核的参考资料：保存来源、适用条件、审阅日期/版本，先用关键词检索；只用于有明确依据的非时效知识，不把模型内置知识标成检索证据。不引入向量库/Redis；正式用户私人模板仍按V0.2。
- 复用公开检索缓存：在供应商授权范围内缓存去标识查询和结果，并记录有效期。未去标识或含敏感条件的请求仅限本人缓存，不跨用户共享目标、健康信息或完整对话。价格/时效信息采用更短有效期，仍需具体策略与许可审查。
- 按领域读取官方资料目录、RSS或结构化数据接口：可减少全网检索与HTML抓取，但覆盖窄、更新/许可/限流需要逐渠道验证；论文元数据/摘要也不是已验证行动建议。
- 用户自愿提供资料或摘录：注明user_provided与提供时间、原链接；不伪装成服务器抓取成功或事实已核验。该替代路径尚未实现。
- SearXNG可自托管聚合检索并启用JSON [官方API](https://docs.searxng.org/dev/search_api.html)；它依赖上游引擎，需承担服务器、维护和访问限制，不是保证永久免费/稳定的自有全网索引。不是目前Windows+iOS+Workers小团队的首选路径。

减少无用搜索、避免重复、控制进入模型的正文长度，比只压低搜索单价更重要。评价口径应是每份可审阅草稿的总费用与有效证据率，包含模型/抽取/失败和人工维护，不采信营销排名作为本项目实测。

## 4. 拟实现的服务边界

SearchProvider.search与现有ResearchProvider.read分开。前者调用固定搜索服务HTTPS endpoint，后者读指定URL；供应商APIKey仅服务端。不要沿用当前四域名网页读取白名单去丢弃所有搜索结果，也不对返回的任意URL自动fetch；任意网页读取需单独完成DNS/IP/跳转/大小/超时SSRF校验或受控抽取Provider。

建议统一请求：query、language、maxResults、站点/时间过滤。统一结果：provider、providerRequestId、query、searched_at，以及各条source_id/title/url/snippet/content_optional/content_kind/published_at_optional。source_id由后端生成；站点评分/权威标签作为辅助信息，不证明事实成立。

区分供应商摘要、供应商内容、真正网页读取和用户提供摘录。searched_at不是网页retrieved_at，发文时间不是访问时间；缺失字段保留未知，不制造时间或“已核验”状态。结果按证据类型私有存储，去重/选少量相关片段后给模型，不把整页或供应商生成答案无区别投入上下文。

## 5. Harness与持久步骤

1. 从用户已确认条件判断知识缺口，生成最多3条去标识查询；不发送姓名、邮箱、完整对话/病史。
2. 用户点击开始研究，服务端核对owner、Goal revision、安全状态、预算并原子保留搜索尝试。
3. Cloudflare Workflows调用固定SearchProvider并持久保存结果、request_id、usage/费用状态和检查点。先用每查询最多5条结果的可控设置，实际内容数量/字数预算另设，不扩大当前澄清上下文。
4. 校验来源结构、过滤重复/不适用结果，记录具体支撑的claim与不确定项；不足时标partial或needs_input。
5. DeepSeek读取最少必要的条件与不可信资料，生成PlanDraft；资料不能控制工具/权限。计划里的引用ID必须存在于本人目标的已保存研究快照，不允许模型编造URL或当次搜索时间。
6. Schema/任务依赖/投入与预算/领域规则校验，再生成修订点；第一版最多一次模型修订，避免无限循环。之后用户审阅，SchedulingService确定性检查合法排程。
7. 执行反馈只调整必要的未来内容，保留PlanVersion和真实执行历史。

付费搜索与公开GET的重试策略不同：默认不假设供应商支持幂等键。提交后超时/崩溃，若无法确认结果和扣费，标unknown并保留预算占用，不自动重搜或切换供应商；禁止直接复制现有免费网页来源步骤的自动重试。后续付费模型阶段同样需要账本/检查点。备用Provider只在已配置、用户授权及共享总预算内启用，不作为无限重试环。

## 6. 实施顺序与验收

先实现通用接口/安全DTO/预算与尝试回执，再接一个搜索Adapter和Cloudflare真实请求；使用同一组学习、健身、护肤的中文/英文检索问题评估有效证据、正文可用性、时效/来源、延迟、错误率和总成本。广告、冲突结果、缺正文、假引用、注入文字、额度不足和网络不明均入评估。未在Cloudflare实际测试的供应商不标上线。

随后将检索接到已确认条件与PlanDraft，展示来源/未知/投入、拒绝不合法任务与引用。没有搜索凭据时只跑模拟测试，明确未验证；不自动开通付费或购买套餐。手填测试链接失败不阻断所有目标，内容不足时通过其他有效来源或明确needs_input处理。
