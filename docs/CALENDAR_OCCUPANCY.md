# 账号已有占用（首批）

此功能只记录用户确认的固定占用，供时间预览避让；没有批准或创建目标任务、读取Apple Calendar、安排提醒或移动固定事件。

## 聊天与确认

在目标聊天点击「记录已有占用」，Agent给出具体日期示例。可回复 `已有占用：北京时间，2026-10-20 09:00-18:00`（日期换成未来31天内）；支持UTC/Asia/Shanghai，最多7个不重叠同日窗口。重复工作日规则、含糊日期、附加指令不猜测，免费补问具体日期；占用上下文中的裸时区日期也按占用解释，显式可用时段或排程请求才切换用途。

busy-chat-v1提议保存在私有agent run，仅用户「确认保存已有占用」固定回复、紧邻提议及有效Goal/聊天/账号日历版本通过后写入。相同时间已保存的不重复添加；独立事件可重叠，排程内核合并避让，不替用户移动或解除占用。事件使用通用标题「已确认占用」，原文只留在目标聊天，不向模型或日志复制日程标题。

每Goal最多40轮这类免费消息，每账号最多500条保存的占用；不调用模型/搜索/邮件，也不占其日额度。首批仅创建/读取，修改、取消、历史清理和重复规则待后续，不声称完整事件管理。

## 数据与原子性

0017新增calendar_states与calendar_events。owner来自已验证会话；source=user、fixed=1、UTC毫秒起止及IANA时区，owner/时间唯一、起止与枚举约束。记录source run/Goal作为可为空的依据链接。占用是账号事实，删除源Goal只清空链接、保留占用；删除账号级联清理。

确认D1 batch同时条件claim成功run、创建/递增calendar_states版本并设置提交标记、由同标记插入全部事件、用户/助手消息。版本/只读/在途/配额检查与源提议保护；任何事件失败整批回滚。重放只读同回执，不再次递增版本/插事件。未来修改/取消Service必须在同事务递增账号日历版本，不能直接写表绕过版本。

## 排程快照与真实列表

一次/一周提议通过一致D1 batch读取账号日历版本与已有事件，冻结本周期交叠占用ID/起止；确认前检查版本，conditional INSERT再检查。内核busy使用此快照，客户端也拒绝交叠结果。任意本账号日历变化保守地使旧提议/预览失效，含范围外变化；旧无日历快照的历史可读但标为失效，需要重新提供时段核对。其他账号变化不影响本人。

这只核实已保存的账号占用；未记录不代表没有日程，领域休息/资源/阶段周期仍需核对。预览没有写入目标任务，完整schedule_proposals/PlanVersion和最终一次批准事务仍未接通。

GET /api/v1/calendar/fixed-events?from=UTC毫秒&to=UTC毫秒：已验证本人、半开相交查询、跨度最多31天，返回schema_version/from/to/revision/events。拒绝额外参数、非法范围；没有写入接口。日志仅固定路由模板，不记录查询或私人内容。

日历Tab替换原M0演示，展示过去24小时至未来30天内的真实已确认占用、时区和版本，账号切换/离开取消读取；尚无目标任务、日/周选择器、反馈或通知功能。结合04-calendar的黑白固定事件卡片，仅完成首批真实占用列表。
