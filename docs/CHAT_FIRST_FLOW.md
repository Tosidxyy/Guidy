# Guidy 对话到方案的主流程

> 2026-10-11 用户明确纠正交互方向。本文是目标设计及改造验收，不表示已经实现；产品要求以 [PRD](PRD.md) 为准。

## 用户体验

规划阶段只有目标内的 Agent 聊天和最后的方案草稿。Agent 主动询问达成标准、必要时间、资源、预算及限制，按目标需要补问，不让用户填 Slot、组装搜索查询、挑选搜索记录或操作任务生成接口。底部仍为目标｜日历｜我的；日历与执行反馈在方案确认后使用。

条件、研究来源、用量回执、运行步骤和版本是后台结构，不在主流程展示字段表。研究时聊天可显示简短真实状态，如“正在查找适合初学者的资料”；用户不需要逐步点击。依据和假设在最终草稿按需展开，不展示模型内部推理。失败在聊天说明并给出可恢复动作，不伪称已完成。

例如用户说“想开始学英语”，Agent问“主要想达到什么效果？”，再根据已有回答询问可用时段。用户答“工作日晚上八点后，每次半小时”，系统在后台提取候选时间；仍不知道哪些工作日可用或时区不确定时，在聊天补问。不能将“每周180分钟”自行变成每天某一时段。

用户说“每次太长，改成20分钟”时，Agent提出局部调整后的草稿或差异，不要求到数字表单操作。已有不可变草稿、审阅、稳定任务ID及执行历史保留。

## 内部条件采集合同

- 模型只提出问题、结构化提取建议与 PlanDraft，不能直接写业务表或调用入历写接口。受控 harness 校验后通过业务 Service 保存来自用户的明确事实，不以模型猜测或助手文字作为用户确认。
- 每项候选携带来源用户消息/run、原文依据、提取规则版本、目标版本及待确认/已明确/未知状态。值与原文的对应关系、字段语义和结构范围由运行时规则检查；原文匹配不能独自证明分类正确。
- 用户对明确问题给出的无歧义答案可以在后台记录，不额外要求逐字段点击“确认”。推断、单位/时区歧义、相互矛盾或风险条件在聊天中澄清；可选未知保留未知，不填假值。
- 通过 owner、expected revision、幂等及原子保存保护内部状态；保存用户事实与生成提问的版本衔接必须明确。旧回复/重复消息不能覆盖新回答；撤销/纠正只更新相关条件并标记旧证据/方案适用性。
- 未知的非关键条件可生成带假设草稿；安全关键条件缺失时继续问；一般可用时段未知允许标为假设先给候选，不因达到软轮次预算而绕过。具体时间保留 IANA 时区，本地时间与重复意图，服务端转换和排程验证。

这会替换现行 clarify-v2 的“建议→条件页手工填入→保存”桥接；不能只隐藏页面或放开旧校验。现有三字段、纯文本/逐字提取协议不能直接宣称已经支持预算、具体时间窗和自动流程。

## 后台研究与计划

达到当前阶段的条件要求后，harness判断知识缺口，在授权的限额内组织查询、调用搜索、筛选证据、生成结构化草稿并校验。没有外部知识缺口时不强制搜索；不得由客户端轮询重复启动模型或付费搜索。

每阶段保存输入版本、Job/尝试ID、检查点、用量与安全状态。重复派发、网络结果不明或App离开后恢复遵循既有幂等/unknown规则，不能无限自动重试或重新扣费。搜索内容是证据数据，不成为系统指令；引用未核实状态保留。当前手动搜索和来源选择接口作为过渡底层能力，不等于自动编排已完成。

## 一次批准与自动入历

最终草稿内展示行动内容、阶段、预计投入、关键假设/风险、资料依据入口，以及经过 SchedulingService 检查的拟安排日期/时间与时区。排程预览合并在草稿，无独立必经页面或正常路径的第二次批准。

用户点击“确认方案并安排”授权采用该具体草稿及其安排；Service再次检查归属、版本、硬冲突、依赖、间隔、截止和前置条件，通过后原子创建生效 PlanVersion、任务实例及提醒意图。用户不用逐条拖入日历，LLM不执行写表。确认前不写日历。

2026-10-13用户明确修正：具体可用时间未知不再阻塞方案与建议日程，Agent直接基于现有信息给出候选安排，默认时区/时段必须标明假设，不当作用户已确认事实；用户可随后追加没空日期或偏好，局部调整。已知硬冲突仍避让，不能把候选说成已生效或可用性已核实。确认提交时若日历或方案已变，拒绝旧提交并更新草稿供重新批准，不在旧授权下静默更换时间或移动固定事件。重复确认和中断恢复只能得到同一回执，不创建重复实例。

成功明确显示“已安排到日历”；提醒设备同步成功、待同步或失败单独呈现，入历不等于提醒已送达，也不等于任务完成。通知权限按既定首次启用提醒时请求。

## 改造顺序与验收

1. **聊天采集闭环**：受控保存明确用户回答、保留依据与未知、同一聊天继续下一问题；用户无需进入条件页即可达到研究准备。覆盖重复/矛盾/旧版本/风险/跨账号/恢复。
2. **聊天触发研究与方案**：按需自动查询、证据选择、生成/校验的持久运行；离开重进可恢复，客户端不触发重复调用。没有搜索必要的目标也有合法生成路径。
3. **草稿内修改与排程预览**：自然语言改时长/频次/条件，确定性时间窗与冲突检查，拟安排包含在最终草稿；没有明确时间则用已披露假设生成候选，用户后续追加限制；不把默认窗口保存为用户确认事实。
4. **一次批准自动入历**：原子确认/实例/提醒意图与幂等恢复，确认前零日历写入；日历变化需重新审阅，提醒状态与执行反馈分离。
5. **收拢正式入口**：聊天闭环可用后，条件表单、手动资料搜索/选择、数字审阅页退出普通主路径；已有数据和版本不能删除，诊断入口仅在明确开发模式下保留。不得用隐藏入口替代上述能力。

本轮仅确认需求与改造计划。现有数字审阅保存/恢复的真机反馈通过，证明现有技术能力，不等于用户接受表单作为最终产品。

## 2026-10-11 用户补充：至少三项与停止提问

至少询问期望成果、投入时间、当前基础/资源与关键限制三个不同信息点。未知可保留；委托安排由Agent提供待接受的投入建议，不反复逼用户报时间。三个信息点各问过一次即可中止本段澄清，停止后按现有信息准备草稿，缺项列假设；批准入历前再校验必需条件。当前中止状态已接持久自动研究/草稿编排；只在成功完成时展示方案，失败或未知不会声称已生成。

## 首批自动链路已接通

停止→持久后台任务→Agent研究判断/按需通用搜索→来源筛选→strict草稿与未知假设，结果留在聊天，不经过人工Slot/搜索表单。重新进入仅恢复进度；失败未知由明确动作处理。当前证据筛选是正文/摘要可用性取最多三项，不是完整语义核实；自然语言改稿、领域评估和一次批准自动入历仍未完成。

### 单项时长/频次调整已接通

聊天中输入明确的一项数字修改→差异卡→用户采用→新审阅版本→聊天展示；无需填写数字表单，不调用模型/搜索，原稿和任务身份保留。只支持确定性可验证的时长/频次，复杂/多项/含糊需要重新说明；全文AI改写、删改依赖、时间窗/批准入历继续按后续任务推进。

## 2026-10-13 用户指定的卡片交互

用户点击Guidy！进入占据页面的问答卡片。卡片显示一个Agent问题和回答区，箭头发送并进入下一问题；历史问题/回答可左右滑动回看。至少三个不同核心问题后提供「开始制订」「继续问答」，不展示Slot、搜索记录、研究来源操作或后台阶段控制面板。继续问答仍可补充目标信息；开始制订由后台按需研究/生成并自动附假设明确的建议时间。

结果是按日期选择的建议日程，选一天查看当天任务/步骤；未找到时间的任务如实标出。建议不等于已批准入历，最终确认能力仍按后续服务实施。后台失败保留回答与草稿，异常状态才提供必要恢复动作。既有数据/来源/依据仍保存，移除的是普通界面入口，不删除记录或声称检索结果已核实。

当前卡片「开始制订」若回答区尚有输入，会连同这条回答一起发起制订，不另付费生成下一问，也不把未分类回答假填Slot；最近用户信息最多8条/各200字随Job冻结，原文仍在私有消息保留。继续问答会发送当前输入或请求新问题，不是空按钮。当前默认建议只覆盖第一阶段一周；通用自然时间、完整阶段周期、最终批准入历仍未完成。明确不可用星期规则是保守首批，不替代全面语义纠错。
