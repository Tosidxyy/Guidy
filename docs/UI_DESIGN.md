## 1. 设计目标与范围

### 1.1 设计原则

1. **Goal-first，Chat-second**：从目标卡片、今日任务进入具体场景；对话只承担创建、澄清、解释、调整，不替代结构化页面。
2. **AI 的建议不等于已执行操作**：研究中、草稿、待批准、已生效、同步失败必须明确区分。
3. **最少必要信息**：优先逐个关键问题；显示为什么问、是否可跳过；不把首次使用变成冗长问卷。
4. **不假装有确定答案**：显示信息来源、查证日期、估算与假设；商品价格、健康相关结论不能凭空给出。
5. **尊重用户自主性**：新增日历任务、批量移动、重大开销变化均先预览再确认；通知可暂停。
6. **先实现完整闭环，再追求花哨视觉**：设计以 Windows 开发 + iPhone 真机测试的独立开发效率为约束。

## 2. 视觉语言（Guidy 黑白品牌基线）

- **定位**：克制、可信、有温度的目标执行工具；品牌标识与主操作以黑白为主，卡片分组、留白、文本层级优先。
- **系统**：支持 Light / Dark；颜色走 Tokens，尊重用户系统主题。
- **字号**：遵循 iOS Dynamic Type；标题层级清楚，正文不依赖固定像素高度。
- **触控**：主要按钮触控区建议至少 44×44 pt；表单与操作应可单手完成。
- **颜色**：计划草稿与已生效不能只依赖颜色区别；同时使用文案及状态图标。

| Token | Light 建议 | Dark 建议 | 用途 |
| --- | --- | --- | --- |
| `surface.base` | `#F7F7F5` | `#0D0D0D` | 背景 |
| `surface.card` | `#FFFFFF` | `#1B1B1B` | 目标卡/信息卡 |
| `text.primary` | `#151515` | `#F5F5F3` | 标题与正文 |
| `text.secondary` | `#686868` | `#ADADAD` | 提示与辅助信息 |
| `accent.primary` | `#111111` | `#F3F3F1` | 主操作；深色模式需配合反色文字 |
| `status.success` | `#267553` | `#7ACDA5` | 仅状态语义色，不是品牌主色 |
| `status.warning` | `#9A6423` | `#E2B76D` | 约束冲突/待确认 |
| `status.danger` | `#B84B50` | `#F39AA0` | 风险/错误 |

> **品牌约束**：Guidy 主视觉仅黑/白/中性灰；绿色/橙色/红色只在状态语义需要时使用。图标设计见 [BRAND_GUIDE.md](./BRAND_GUIDE.md)。色值仍需真机验证对比度。

**Spacing scale**：4 / 8 / 12 / 16 / 24 / 32 pt；卡片圆角建议 14–18 pt；内容区域建议左右 16 pt；按钮垂直高建议 48–52 pt。采用主题 Tokens，避免各页面硬编码。

**组件清单**：`GoalCard`、`TaskRow`、`PlanStateBadge`、`QuestionCard`、`AnswerOptions`、`ResearchStage`、`EvidenceItem`、`PlanPhaseCard`、`ConflictCard`、`ScheduleProposalCard`、`RevisionDiffRow`、`FeedbackActions`、`ReminderStatus`、`PrivacyNotice`、`OfflineBanner`、`EmptyState`。

## 3. 关键页面详细设计

### P01 登录/引导

**目标**：用一屏说明产品价值，解释数据最少收集原则；账号登入后才能稳定同步跨会话目标。

- 首次进入：产品一句话介绍、三个短步骤（提出目标→确认计划→按时执行）、登录入口。
- 支持邮箱验证码/魔法链接作为首发方案；若后续增加第三方登录需单独检查 Apple 登录审核规则。
- 提示：通知授权在用户**第一次实际开启提醒**时询问，不在启动页弹系统通知权限。
- 登录失败：保留输入、提供重试和错误反馈；不显示原始服务端错误堆栈。

**M0 当前认证边界**：入口为「我的 → 登录」，保持三个 Tab。已接 Better Auth/D1 的真实 OTP/会话/退出；当前可用本地收件箱，Resend 发信适配待 secret/真实收信验收。界面依据服务端确认的投递方式显示收件箱命令或查看邮箱提示，邮件失败不伪装成已发送；固定演示码已替换。目标/日历仍是演示数据，不能把账号登录当成业务闭环已完成。

验证码错误/过期/限流由服务端判定，保留输入并显示通用失败和重新获取操作，不显示原始堆栈、固定 OTP 或假成功。前端不读取公开取码接口；开发者通过 Windows 本地命令查看收件箱。退出失败保留明确重试反馈，不能把未确认撤销说成成功。

演示验证码的输入展示允许数字分隔符/全角数字规范化；其他错误字符必须保留并提示，不能被清洗成有效码。字段有标签/可访问提示，错误同时使用文字与边框；验证码页自动聚焦，邮箱错误返回对应字段。Native 键盘、字体和读屏需单独真机验证；浏览器焦点结果不替代 VoiceOver。

### P02 我的目标（默认首页）

```text
┌───────────────────────────────┐
│ Guidy             🔔   ⚙   │
│ 今天，把目标推进一点点          │
│ [ + 创建新目标 ]               │
│ 今日待办 2 项  ·  待确认计划 1 │
│ ┌───────────────────────────┐ │
│ │ 🏋 建立训练习惯           │ │
│ │ 进行中  ·  下次 18:30     │ │
│ │ [查看今天任务]            │ │
│ └───────────────────────────┘ │
│ ┌───────────────────────────┐ │
│ │ 📚 准备英语考试           │ │
│ │ 计划草稿  ·  待审批       │ │
│ │ [查看计划]                │ │
│ └───────────────────────────┘ │
│ 目标          日历          我的│
└───────────────────────────────┘
```

**必须展示**：目标标题、状态（草稿/待确认/进行中/暂停/完成）、下一项动作或阻塞理由、创建按钮。**不使用“第 8/21 天”冒充执行完成率**；V0.2 可单独显示观察日历天数与任务完成率。

**交互**：点击卡片进入目标工作台；右侧更多操作：暂停、恢复、归档（删除入口在二级菜单并二次确认）；空列表引导创建首个目标。加载使用骨架卡；离线时展示本地缓存和“上次同步”说明。

### P03 创建目标 / 动态澄清

当前实现的输入准备：账号目标详情内进入三步条件确认（期望结果、可投入时间、限制条件），可以选择暂不确定、确认保存和继续修改；已保存摘要标明来自用户，未保存输入与已确认信息分别呈现。此阶段为固定输入准备，不当作 AI 动态问题或研究结果；时间仍是说明，不直接操作日历。仅草稿可保存，暂停目标需先继续；离开前确认保存，系统返回手势/键盘仍需真机验收。

**创建**：大输入框“最近想完成什么？”、示例标签（学习/健身/护肤）只用于启发，不限制目标分类。提交后立刻持久化草稿 Goal，以防网络中断。

**对话复合组件**：

1. 用户目标陈述卡：可编辑。
2. Agent 当前问题卡：**每次优先一个最关键问题**；选项 + 补充文字 + `暂不确定`。
3. 已确认约束摘要：预算、时间、期望、已有资源等；可修改/撤销，标注“来源于用户”或“尚待确认”。
4. 明确的操作：`继续`、`先生成可编辑草案`（仅在缺失的不是关键安全字段时可用）、`暂停并保存`。

**规则**：不重复问已有答案；风险必要信息缺失时不能进入最终定稿；不要强迫用户提供健康资料，也不要把“先生成草案”伪装成已具备安全信息。

### P04 研究与依据

首批实现为“研究资料与来源”准备页：用户提供有限官网链接和待核对问题，显示读取/失败/未核实、访问时间、短摘录和用户填写限制；旧目标版本标出适用性待核对。原始网页可打开，失败可填回明确重试，未提交输入离开需确认；表单独立底栏、读取状态可手动刷新。本阶段没有自动搜索、事实结论或后台Job，不把短网页读取表现成完成研究。

状态：`排队中 → 查找资料 → 核实与对比 → 生成草稿 → 完成`，以及 `部分完成 / 失败 / 已取消`。进度只显示确定阶段，不展示伪造的百分比或“AI 正在思考”的具体内部推理。

研究结果卡展示：`结论`、`信息来源 URL/名称`、`检索时间`、`适用条件`、`不确定事项`。对商品价格和成分浓度不能无依据推断。页面关闭、手机锁屏后可重新进入并恢复服务端 Job 状态。

### P05 计划工作台

建议内容顺序：

1. 顶部：目标名、阶段、计划版本、状态与 AI 风险提示；按钮 `修改要求`。
2. 方案概览：目标可执行程度、所需时间/预算范围、需要用户决定的前置条件。
3. 阶段任务卡：标题、预计时长/频率、时间窗口、先决任务、资料依据入口、能否安排。
4. 证据与假设：来源列表、未证实信息、无需额外购物也可执行的替代方案（如适用）。
5. 底部固定操作区：`继续调整` / `预览日历安排`；当资料不充分或必需条件缺失时禁用最终确认，并解释原因。

**编辑约束**：改变预算、训练日期等不应直接覆盖生效数据，而是创建差异草稿。研究成本预估与最终结算不同，需明确标注。

### P06 排程预览与冲突说明

顶部展示“待确认，不会修改原日历”。按日展示建议时段（本地时区）、不可排入的 Task 与原因、可以替代的候选时间；重要前置依赖为阻塞状态。

- `确认并加入日历`：传 `proposal_id + expected_goal_version + Idempotency-Key`；成功后跳转日历。
- `修改时间`：编辑柔性任务的时间偏好或重新请求候选；不移动用户手动创建的固定事件。
- `取消`：原计划及通知不变。
- 409 版本冲突：提示“日程已改变，请重新预览”，禁止提交过时草稿。

**冲突显示模板**：`冲突类型` + `影响对象` + `不能直接安排的原因` + `建议操作`。例如“周一 19:00–20:00 已有固定活动，因此无法安排 45 分钟需要专注的训练”。

### P07 内置日历与任务反馈

**V0.1 默认视图**：顶部日期切换 + “今日 Agenda 列表”，优先确保不同屏幕和 Dynamic Type 适配；日/周可切换。任务类别并非互斥的业务判断基础，`固定事件` 和 `已确认柔性任务` 显示不同样式。

**Task Detail**：标题、来源 Goal、计划版本、开始/结束、前置依赖、提醒状态、反馈动作。完成状态四类按钮：`已完成`、`部分完成`、`延期`、`跳过`。`未响应`为系统推导状态，**不可等同“跳过”**。

点击“延期”→出现候选时间→进入小型差异预览→确认后更新服务端日程与本地提醒。不能安排时明确解释，不无限循环提议同一冲突窗口。

### P08 版本差异预览

版式：`当前生效 Vn` 与 `建议 Vn+1` 的概览，按新增/删除/改期/任务内容变化分组；突出用户新约束与影响范围（时间、预算、任务依赖、提醒）。按钮：`接受调整`、`继续修改`、`保留原计划`。确认失败保持旧计划可用。

对于已执行的历史任务，仅保留真实执行记录；不得因为新版本删除过去完成情况。回退也要重新运行当下约束校验。

### P12 我的（V0.1；V0.2 增加模板资产）

**设计原则**：「我的」是个人信息、用户资产与设置的统一入口，不是内容推荐首页；重要操作应清晰分组，避免堆砌选项。

```text
┌───────────────────────────────┐
│ 我的                          │
│ ┌───────────────────────────┐ │
│ │ 头像  昵称                │ │
│ │ 邮箱 / 已登录状态         │ │
│ │ [查看与编辑个人资料]      │ │
│ └───────────────────────────┘ │
│ 我的内容                      │
│  我的模板                ›    │  ← V0.2 启用
│  我的目标记录            ›    │  ← 返回目标列表/归档
│ 偏好设置                      │
│  通知与提醒              ›    │
│  隐私与数据管理          ›    │
│  语言与时区              ›    │
│  账号与安全              ›    │
│             目标  日历  我的 │
└───────────────────────────────┘
```

- **个人资料**：头像（可选）、昵称、邮箱/账号状态；编辑、保存失败、退出登录分别处理。首次版本只保存必要基础资料，不收集性别/生日/真实姓名作为默认字段。
- **我的模板**：V0.1 在「我的」显示条目及明确的「即将开放」状态（不可进入未实现页面）；V0.2 开放私人模板列表、模板草稿/版本、从自己的计划创建模板与应用向导；V0.3 在列表顶部新增「发现模板」入口，不改变底部 Tab。
- **账户与会话**：退出、导出个人数据、注销/删除账号入口；重要删除需二次确认。
- **目标偏好**：IANA 时区、显示语言、可选的习惯时间偏好；绝不默认要求敏感资料。
- **通知与提醒**：系统权限状态、提前提醒时长、静默时段、通知内容隐私模式、开关及待同步数量。
- **隐私与数据管理**：查看/修改 Goal Slots、说明资料的使用范围、删除私人计划、查看应用数据处理说明。
- **错误恢复**：显示最近同步时间与重试；不能把“计划已经保存”误显示为“提醒已经成功安排”。

**页面状态**：未登录（引导登录）、已登录、资料加载失败、模板列表为空/待开放、通知权限受限，均给出真实状态与可执行操作。

### P09/P10/P11（后续版本）

- **21 天**：称为启动观察期，区分 `第 N 天/共 21 天`、`安排任务数`、`已完成数`、`有反馈天数`；禁止文案“21 天必然养成习惯”。
- **私人模板**：入口固定为「我的 → 我的模板」。展示模板必填字段与动态补问机制；模板路径不携带原作者个人数值/对话。实例化必须创建**新的 Goal/Plan**。
- **公共模板**：V0.3 通过「我的模板 → 发现模板」进入。发布前展示脱敏预览、可申请资格、审核状态；`完成 21 天记录` 不等于 `科学验证有效`。支持投诉、下架、撤回与适用条件说明。

## 4. 关键交互与状态规范

| 场景 | 首选交互 | 必须处理的异常 |
| --- | --- | --- |
| 创建目标 | 文本输入 → 持久草稿 → 动态问题 | 空内容、网络失败、重复点击 |
| 研究 | 阶段状态 + 依据卡片 | 长时间运行、退出重进、超预算、来源不可用 |
| 计划确认 | 草稿 → 排程预览 → 二次确认 | 任务不合法、硬约束冲突、版本过期 |
| 提醒 | 用户授权 → 本地调度 → 同步回执 | 系统拒绝、App 尚未同步、已改期旧提醒 |
| 执行反馈 | 一键状态 + 可选原因 | 离线、重复操作、已提交记录纠错 |
| 计划修改 | 自然语言/直接编辑 → 差异卡 → 确认 | 影响范围扩大、与现有时间冲突、回滚 |
| 模板应用（V0.2） | 输入必填项 → AI 条件补问 → 新计划 | 不适用条件、隐私资料、过期来源 |

### 4.1 客户端页面状态标准

所有主要数据页面支持：`loading`、`ready`、`empty`、`recoverable_error`、`permission_blocked`、`offline_cached`。研究任务额外支持 `queued/running/needs_input/completed/failed/cancelled`。不得把网络断开误写成“Agent 已取消”。

### 4.2 状态文案

| 内部状态 | 用户可见文案 |
| --- | --- |
| `plan_draft` | 计划草稿（尚未安排日历） |
| `awaiting_approval` | 等待确认 |
| `active` | 已生效 |
| `blocked` | 前置条件未满足 |
| `notification_needs_sync` | 日程已保存，提醒待手机同步 |
| `research_partial` | 部分资料尚未核实 |
| `execution_unknown` | 尚未反馈 |

## 5. 通知设计

- **授权时机**：用户第一次确认计划且主动开启提醒时，先展示应用内说明再弹系统权限弹窗。
- **设备通知**：服务端 `notification_intents` 存储提醒意图；App 根据有效时间窗口使用 `expo-notifications` 本地调度、保存系统通知 ID 并回报同步；计划修改后重建对应提醒。
- **不保证强实时后台变更**：App 被关闭且不能运行时，云端对计划的调整可能无法立即撤销已注册的旧通知。界面提供同步状态说明；未来再引入远程推送作为补充。
- **默认频控建议**：每项任务最多“提前一次 + 到点一次”，可关闭；支持静默时段和通知隐私隐藏。
- **通知点击**：尽量 deep-link 至具体 occurrence，允许完成、稍后、跳过等操作；点击后写服务端反馈，失败可再次同步，不能只更新动画。

## 6. 无障碍、隐私与国际化

- 支持 VoiceOver 元素标签及操作提示；按钮不只使用图标传达语义。
- 支持 iOS 字体放大、减少动态效果、浅色/深色、足够对比度和安全区域。
- 日期和日程按用户的 IANA 时区渲染；同时清楚区分绝对时间与任务的本地重复规则；跨 DST 的时间必须明确确认或给出替代时间。
- 文案先支持简体中文；架构预留 `i18n` 键与复数形式，不在业务数据中硬写所有 UI 字符串。
- 健身/护肤/补剂场景的敏感问题提供目的说明，并允许用户拒绝；如无法安全定稿，要明确解释，而不是继续猜测。

## 7. 设计评审与验收用例

**D-01 首次创建**：新用户从首页提出“我想开始学英语”，可通过动态提问保存 Goal 草稿；退出再进入不丢关键输入。

**D-02 研究透明**：用户可打开来源并看到“何时查证”；无来源的关键专业结论不会被呈现成既定事实。

**D-03 排程冲突**：已有固定日程时，排程预览明确阻断冲突并解释原因，不偷偷挪动固定事件。

**D-04 提醒同步**：计划确认但系统通知未授权时，日程显示已保存、提醒显示未开启，而不是成功状态。

**D-05 自然语言修改**：用户改为“周一不方便”，出现受影响任务的版本差异，确认前旧计划维持不变。

**D-06 执行反馈**：部分完成/跳过不记作完成；修改计划后过去的真实完成记录仍可查。

**D-07 特殊尺寸**：至少在一部实际 iPhone、系统大字体、深色模式下验证首页/对话/计划/日历/我的与安全区域，不能仅用 Web 预览代替。

**D-08 我的导航**：底部始终只有「目标｜日历｜我的」。V0.2 从「我的 → 我的模板」完成私人模板应用；V0.3 从「我的模板 → 发现模板」进入公开模板浏览，不出现第四个 Tab。
