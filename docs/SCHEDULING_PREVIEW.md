# 排程预览内核（首批）

本轮实现 `backend/src/scheduling/preview.ts` 的纯函数 `previewSchedule`，尚未接聊天、API、数据库或日历。它不是完整 M2，也不是批准入历服务。

## 输入边界

- 上游必须明确任务实例、时长、依赖、UTC epoch 毫秒时间窗及 IANA 时区。每周频次、尝试每周60分钟、阶段编号不能自动变成具体日期或真实空闲时间。
- `schema_version=1`；每类列表最多100项，预览跨度最多31天。窗口可为空，空窗口返回未安排；非法输入、未知依赖、环、重复身份/依赖整体拒绝。
- 任务可带 earliest/deadline/fixed_start、series_id 和 minimum_gap_minutes。系列间隔从前一实例结束到后一实例开始，采用双方较大的间隔；所有任务占用同一用户的时间。
- completed_dependencies 只接已验证的历史完成时刻，不能来自通知送达或模型推测；不得晚于预览起点。上游负责 owner、真实日历快照、来源确认与版本一致性；本内核不做身份认证。
- 本地时间转换、DST歧义/不存在的时刻、重复规则展开、阶段周期、资源互斥及领域额外约束尚未实现。IANA 名称必须有效；UTC具体时刻由上游确认，不能用固定 UTC+8 替代时区。

## 算法与结果

先合并重叠/相邻窗口，再按稳定任务身份顺序选择依赖已处理的任务。在合法窗口中跳过已有占用和拟安排，选择最早能容纳整个任务的位置；不拆分任务，起止采用半开区间，结束时刻可紧接下一任务。

结果固定 `status=preview_only`、`strategy=stable_topological_earliest_v1`，包含 placements 和 unplaced。后者区分依赖未安排与无合法时间窗。没有合法位置时不会挪动固定时间、越过截止时间或捏造空闲。

这是有界贪心算法，不保证最优，也不保证发现所有可行解；较早任务可能占用较后固定任务的位置。不能把 `no_legal_window` 表述为数学上不存在方案。备选安排、优化与更细冲突解释待后续实现。输入和旧数据不修改，成功预览也不代表已确认、已入历或提醒已安排。

## 验证及下一步

自动测试覆盖占用/半开边界、依赖与环、固定时间/截止/不拆分、间隔、跨日、DST真实时长、无窗口、畸形输入及40组合法性检查。DST测试只证明 UTC 时刻的时长处理，不证明自然语言本地时间转换。
