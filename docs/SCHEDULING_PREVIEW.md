# 排程预览内核（首批）

`backend/src/scheduling/preview.ts` 提供纯函数 `previewSchedule`。聊天已接具体时段核对、首阶段各项一次或一周频次试排，通过既有 messages API 保存私有对话产物；已接账号已确认固定占用快照，尚未接批准入历服务，不是完整 M2。

## 输入边界

- 上游必须明确任务实例、时长、依赖、UTC epoch 毫秒时间窗及 IANA 时区。每周频次、尝试每周60分钟、阶段编号不能自动变成具体日期或真实空闲时间。
- `schema_version=1`；每类列表最多100项，预览跨度最多31天。窗口可为空，空窗口返回未安排；非法输入、未知依赖、环、重复身份/依赖整体拒绝。
- 任务可带 earliest/deadline/fixed_start、series_id 和 minimum_gap_minutes。系列间隔从前一实例结束到后一实例开始，采用双方较大的间隔；所有任务占用同一用户的时间。
- completed_dependencies 只接已验证的历史完成时刻，不能来自通知送达或模型推测；不得晚于预览起点。上游负责 owner、真实日历快照、来源确认与版本一致性；本内核不做身份认证。
- 本地时间转换、DST歧义/不存在的时刻、重复规则展开、阶段周期、资源互斥及领域额外约束尚未实现。IANA 名称必须有效；UTC具体时刻由上游确认，不能用固定 UTC+8 替代时区。

## 算法与结果

先合并重叠/相邻窗口，再按稳定任务身份顺序选择依赖已处理的任务。在合法窗口中跳过已有占用和拟安排，选择最早能容纳整个任务的位置；不拆分任务，起止采用半开区间，结束时刻可紧接下一任务。

结果固定 `status=preview_only`、`strategy=stable_topological_earliest_v1`，包含 placements 和 unplaced。后者区分依赖未安排与无合法时间窗。没有合法位置时不会挪动固定时间、越过截止时间或捏造空闲。

这是有界贪心算法，不保证最优，也不保证发现所有可行解；较早任务可能占用较后固定任务的位置。不能把 `no_legal_window` 表述为数学上不存在方案。备选安排、优化与更细冲突解释待后续实现。输入和旧数据不修改，成功预览也不代表已确认、已入历或提醒已安排。

## 验证及下一步

自动测试覆盖占用/半开边界、依赖与环、固定时间/截止/不拆分、间隔、跨日、DST真实时长、无窗口、畸形输入及40组合法性检查。DST测试只证明 UTC 时刻的时长处理，不证明自然语言本地时间转换。

完整领域约束、独立不可变预览表和批准事务仍需逐项实现；账号固定占用已接入，见[占用合同](CALENDAR_OCCUPANCY.md)。参见 [架构](ARCHITECTURE.md)、[数据库](DATABASE.md)、[进度](TODO.md)。

## 聊天试排协议（schedule-chat-v1）

在已生成的聊天草稿点击「预览首阶段具体时间」，Agent询问具体日期与时区。用户可直接回复 `可用时段：北京时间，2026-10-20 20:00-21:00；2026-10-22 20:00-21:00`；日期应换为未来31天内。首批仅支持明确的北京时间/Asia/Shanghai或UTC、最多7个不重叠的同日时段，24:00、无效日期、跨日文字、其他时区与附带命令不猜测。北京时间当前未来窗口转换为UTC，并保留IANA时区；这不是全时区/DST转换器。

受控解析成功后在聊天展示待核对时段，未运行排程。用户「确认时段并预览」发送固定确认文字，只能确认紧邻的最新提议，服务端绑定本人Goal、当前草稿源、Goal/审阅版本与原始回复run。冻结最早阶段的任务稳定身份/标题/时长/依赖，首阶段各项一次，不展开周频次，不猜测阶段周期/休息间隔/资源/截止要求；范围外依赖不冒充已完成。

确认后内核以声明窗口及账号已确认占用快照计算，避开已记录占用；未记录日程和完整领域约束仍待核对。拟安排/未安排原因保存在新的成功agent run，只读保留旧记录；没有更新Goal/Slot/PlanVersion/日历/提醒。每Goal最多40次该类消息，不调用模型/搜索/邮件、不占模型澄清或方案生成配额；含糊回复在时段问答内仍给受控指导，普通模型聊天保持原额度。

同键同内容重放只读旧回执；错版本/并发聊天不插入。提议/确认的INSERT再次校验最新草稿及审阅版本；条件改变、另端审阅、新生成源或时段过期拒绝旧确认。GET返回过期标志，旧记录保留，界面禁用非紧邻/过期提议；用户提供新时段后需重新核对。确认按钮保留尚未发送的输入。适用性风险历史持续阻断试排，关键词仅首批保守防护，不是完整领域安全审查。

聊天入口、核对卡、拟安排卡沿用Agent/草稿黑白视觉；不新增字段表单或导航。步骤改写、跨阶段多周重复实例、通用自然语言日期、实际占用和方案批准仍在后续范围。

## 首阶段一周试排（first_stage_week_v1）

当前主流程采用Guidy卡片与后台自动建议日程，不再展示排程/来源操作按钮；以下明确时间协议仅用于历史兼容/诊断。旧的一次试排协议/消息/历史保持兼容，取消旧入口的并列展示。一周模式由明确请求或当前harness时段上下文继承，模型不能设置模式；用户需确认新的一周频次规则，旧的一次确认文字不能批准一周提议。

周期从首个可用时段的本地日期00:00开始，连续7天，结束时刻不含；不是默认周一至周日，也不猜测阶段持续几周。仍只支持北京时间/Asia/Shanghai和UTC，最多7个未来明确同日时段，所有窗口须在这个周期内；其余日期重新澄清。核对卡展示周期和总次数。

最早阶段的每个模板任务按最新审阅frequency_per_week展开1–7个独立试排实例，最多42个；原始Task UUID通过series_id保留，实例ID为UUID_ordinal，包含ordinal/repeat_count。用户确认的试排规则为同项每个本地日期最多一次；内核增加max_per_day=1，并把跨日窗口拆成明确日界片段，同项占用整日本地日期，不能把每周三次塞进同一晚。该规则不是领域所需的最短休息间隔，后者仍需核对。

依赖采用明确展示的保守试排规则：本周前置项的全部实例先拟安排，再排后续项；同项的实例按ordinal串联。未排前置实例使下游未安排，范围外依赖不当成已完成；试排顺序不等于用户真实完成，不能作为后续阶段完成依据。聊天已读取账号确认的固定占用及日历版本，传入内核busy并拒绝旧版本确认，未记录日程不能视为空闲。

预览显示已排/未排次数、每次序号和具体日期，原草稿只读不展开覆写。不修改阶段、Task身份、条件、Goal或日历；旧版本、审阅/来源变化、过期、owner/幂等及免费预算规则沿用。客户端另检验周期日界/7天、实例身份/总数、每日一次、原依赖/时长和preview_only，拒绝伪造执行状态。

完整阶段周期、多周展开、全时区DST日界、领域安全/休息约束、未记录的外部日程和批准入历仍未完成；这是明确确认的一周时间试排，不是完整可执行计划。


## 聊天提示与读取恢复修正

时间询问使用简短普通字号问句，schedule_help.example_text与问题分离、默认折叠，可展开查看明确日期示例。旧协议命令和长提示仅在展示层映射为普通聊天，不改写已存消息或确认依据；已有一次问答可显式切换一周，不悄悄改变授权范围。严格日期/时区解析仍保留，未宣称支持任意自然语言时间。

planning-runs状态请求等待上限30秒，失败保留当前已校验草稿、明确状态未更新并提供GET重新读取；离开页面取消读取，未读取成功时禁止新生成/重复排程操作。恢复不新建Job、不调用模型；不能从读取超时判断计划生成失败，也不证明手机网络已根治。

## 2026-10-13 主流程更新：直接给建议日程

常规流程不再询问具体可用窗或提供排程入口。后台Workflow生成草稿完成后，ensureAutomaticSchedule以当前Goal/草稿/审阅/日历版本的稳定键产出首阶段一周建议，默认Asia/Shanghai、从明天起七天每日20:00–21:00候选；window_basis=assumed_default_v1，不能标为用户已确认。仍避让本人固定占用；若完整任务放不下如实未排，不制造完整可执行方案。失败时已存草稿保留，客户端可恢复同键纯排程，不重新调模型；额外排程不计模型/检索配额，不写GoalSlot/任务日历。

GET messages返回最新auto_schedule供重进恢复，原私有run保留；正常结果展示按日历日期查看任务。旧明确窗协议保留仅用于兼容/诊断，不在普通界面并列展示。继续问答支持通用问题，成功用户回复（最多8条、各200字）冻结为dialogue_notes用于下一计划；首次三个核心条件与风险/预算门槛不变。仅对明确「周三没空/星期三没有时间」等整星期补充作保守避让，条件、否定、例子/局部时段不自动解读，不等于任意自然时间改稿已完成。
